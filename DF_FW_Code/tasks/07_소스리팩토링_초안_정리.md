# 작업 07

소스 리팩토링 초안 정리

## 목표

현재 `.inc` 기반 1차 기능 분리를 분석해 Main/Rod의 전역 의존성, 상태 owner, 공개 API와 독립 `.cpp/.h` 전환 순서를 코드 변경 전에 확정한다.

## 현재 기준

- 양쪽 `.ino`에는 `setup()`, `loop()` 위임만 남아 있다.
- 기능 코드는 application `.cpp`에 `.inc`로 포함되어 기존 단일 파일의 선언 순서와 전역 상태를 계속 공유한다.
- 작업 03~06 이후 현재 활성 소스의 compile/link와 protocol 호환성은 미검증이다.
- 초안 기준 문서는 `docs/refactoring/SOURCE_REFACTORING_DRAFT.md`다.

## 관련 영역

- `firmware/DF_Main/src/modules/`
- `firmware/DF_Rod/src/modules/`
- `firmware/DF_Main/src/DF_Main_Application.*`
- `firmware/DF_Rod/src/DF_Rod_Application.*`
- `docs/refactoring/`

## 구현 원칙

- 이 작업에서는 소스 코드를 변경하지 않고 리팩토링 설계 초안만 만든다.
- 현재 동작과 선언 순서를 관찰한 사실과 목표 구조를 구분해 기록한다.
- C++98/03, 고유 접두어, namespace 미사용 및 Variant 분기 미도입 정책을 설계에 반영한다.
- owner나 호출 경계를 확인할 수 없는 항목은 추측하지 않고 보류 항목으로 남긴다.
