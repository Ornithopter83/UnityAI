# 작업 09

Main/Rod 통합 검증과 릴리스

## 목표

현재 Main과 Rod 한 쌍을 재현 빌드하고 실제 장비에서 통합 검증한 뒤 추적 가능한 릴리스 자료를 만든다.

## 현재 기준

- 모든 선행 작업이 완료되어야 시작한다.
- compile/link 빌드는 Codex가 실행하고 flash와 장비 시험은 사용자가 수동 수행한다.

## 관련 영역

- `tools/`, `docs/testing/`, `docs/releases/`, `artifacts/`

## 구현 원칙

- Main/Rod/Protocol 버전을 한 release manifest에 묶는다.
- 수동 결과 없는 항목을 통과로 기록하지 않는다.
- firmware artifact는 일반 Git 추적에서 제외하고 해시와 보관 위치를 기록한다.

## 세부 작업

### A. clean build 실행과 결과 수집

### B. firmware size, map, hash 비교

### C. Main 단독 수동 smoke test

### D. Rod 단독 수동 smoke test

### E. Main–Rod registration/통신/입출력 통합 시험

### F. 장시간 및 오류 복구 시험

### G. release manifest와 알려진 제한 확정

## 진행

잔여 작업 7개 (A, B, C, D, E, F, G)

## 변경 금지

- 실패한 검증을 문서상 통과시키지 않는다.
- 명시적 요청 없이 commit, tag, push 또는 배포하지 않는다.

## 완료 조건

- 모든 필수 수동 결과가 기록되고 Main/Rod/Protocol 한 쌍의 릴리스 manifest가 완성되어 있다.

## 시험 방법

- Codex가 clean compile/link와 산출물 검사를 수행한다.
- 사용자가 flash, Main/Rod 단독 smoke, 통합, 장시간 및 오류 복구 시험을 수행한다.
- 각 수동 시점에 Codex가 체크리스트를 제공하고 결과를 받을 때까지 완료로 기록하지 않는다.

## 결과

- 작업 수행 후 기록.
