# 작업 04

Main/Rod 공유 프로토콜 계약

## 목표

현재 Main과 Rod가 사용하는 ESP-NOW/UART 메시지의 방향, PID, payload 및 제한을 한 곳에서 정의하고 양쪽이 같은 계약을 사용하게 한다.

## 현재 기준

- PID와 문자열 상수가 양쪽 `Common.h` 및 `.ino`에 중복되어 있다.
- 송신은 주로 `pid + payload` 문자열이며 최대 128바이트 고정 버퍼를 사용한다.

## 관련 영역

- Main/Rod `Common.h`, `ENow.cpp/.h`, 수신 handler
- 향후 `docs/protocol/`, `libraries/DFProtocol/`, `tests/protocol/`

## 구현 원칙

- 과거 버전 호환을 목표로 하지 않고 현재 Main/Rod 한 쌍만 검증한다.
- protocol 형식 변경이 아니라 중복 정의 제거가 1차 목표다.
- C 스타일 API, 고정 버퍼, 명시적 길이, 고유 접두어를 사용한다.

## 세부 작업

### A. 메시지 전수 목록 (완료: 2026-08-27)

- 방향, PID, payload 형식, 길이, 응답 및 timeout을 조사한다.

### B. Golden fixture와 계약 문서 (완료: 2026-08-27)

- 현재 코드가 생성/수신하는 대표 byte 문자열을 변경 금지 기준으로 기록한다.

### C. C++03 호환 DFProtocol 인터페이스 (완료: 2026-08-27)

- `typedef struct`, `typedef enum` 또는 익명 enum, `DF_Protocol_` 함수로 구성한다.

### D. Host 호환 검사 준비 (완료: 2026-08-27, 미실행)

- encode/decode, 잘린 입력, 초과 길이, 미등록 PID 사례를 장비 없이 확인할 수 있게 준비한다.

### E. Main의 공유 계약 적용 (완료: 2026-08-27)

- 기존 결과 문자열을 유지하면서 중복 상수와 parser를 교체한다.

### F. Rod의 공유 계약 적용 (완료: 2026-08-27)

- Main과 동일한 계약을 사용하도록 교체한다.

### G. 수동 protocol/Main–Rod 게이트 (미수행: 2026-08-27, 사용자 지시)

- 사용자가 준비된 호환 검사와 실제 Main–Rod 통신 시험을 수행한다.

## 진행

잔여 구현 작업 0개. Host 및 Main–Rod 호환 검증 미수행.

## 변경 금지

- PID 재번호화, payload 재설계, delimiter 변경을 함께 수행하지 않는다.

## 완료 조건

- 현재 Main/Rod 프로토콜 정의가 한 곳에 있다. 대표 메시지 호환 결과는 확인하지 않았다.

## 시험 방법

- G에서 사용자 수동 host 검사와 실제 장비 통신 결과가 필요하다.

## 결과

- 2026-08-27 작업 04-A/B 완료: `docs/protocol/DF_PROTOCOL_CONTRACT.md`에 양방향 PID, 현재 payload 의미, 127바이트 wire 제한과 대표 golden 문자열을 기록했다.
- 2026-08-27 작업 04-C 완료: `libraries/DFProtocol`에 namespace와 C++11 문법 없이 enum, 고정 버퍼, 명시적 길이를 사용하는 encode/decode 계약을 추가했다.
- 2026-08-27 작업 04-D 완료: 정상 encode/decode, 짧은 입력과 비숫자 PID 사례를 담은 `tests/protocol/DFProtocol_HostTest.cpp`를 작성했으나 실행하지 않았다.
- 2026-08-27 작업 04-E/F 완료: Main/Rod의 중복 PID 사용처를 `DF_Protocol_` 심볼로 교체하고 build script가 저장소 `libraries/`를 Arduino library 경로로 전달하도록 변경했다.
- 2026-08-27 작업 04-G는 사용자 지시에 따라 host test, firmware build, 실제 Main–Rod 통신을 수행하지 않았다. Golden fixture와 적용 결과는 미검증 상태다.
