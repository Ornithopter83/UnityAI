# DF Firmware 작업 지침

## 사전 승인 정책 (2026-09-02, 최우선)

- 빌드(compile/link 포함), 테스트, 반복 검증, 추가 조사·탐색은 반드시 사용자의 명시적인 사전 승인을 받은 뒤 수행한다.
- 코드 수정 요청이나 과거 작업의 승인을 위 활동에 대한 포괄 승인으로 해석하지 않는다. 필요한 경우 목적과 실행 범위를 짧게 제시하고 승인 전에는 실행하지 않는다.
- 승인 범위를 넘는 재시도·추가 검증·조사는 다시 승인받는다. 미실행 항목은 미실행으로 기록한다.
- 이 정책은 다른 계획서·작업서·명령서의 자동 빌드 및 필수 검증 규정보다 우선한다.
- 인수인계만 요청받은 경우에는 AGENTS.md와 NewThreadHandoff.md만 읽고 짧게 보고한 뒤 기다린다. 전체 문서 재독, Git 상태 확인, 소스 탐색, 과거 결과 재검증을 자동 실행하지 않는다.

- 작업 전 `DF_FIRMWARE_INTEGRATED_REFACTORING_PLAN.md`, `CurrentWork.md`, `PROJECT_COMMANDS.md`, 활성 작업서를 순서대로 읽는다.
- 한 번에 한 개의 문자 단위 작업만 수행한다. 사용자가 명시적으로 묶음 작업을 요청한 경우만 범위를 넓힌다.
- 완료한 문자 작업에는 완료일, 실제 변경 내용, 확인 근거를 기록하고 잔여 작업 수를 함께 갱신한다.
- `Vm1.0.9.0`과 `Vr1.0.1.0`은 현재 기준 원본이다. 원본과 무관한 사용자 변경을 보존한다.
- 활성 펌웨어는 현재 사용하는 Main/Rod 구성만 지원한다. 과거 전체 원본은 `legacy/`, 활성 코드에서 제거한 구 코드는 저장소 루트의 `deprecated/`에 보존한다.
- `deprecated/` 코드는 활성 펌웨어에서 include하거나 빌드하지 않으며 현대화하지 않는다.
- 프로젝트 작성 코드는 C++98/03 문법 범위로 제한한다. 람다, 스마트 포인터, `auto`, `nullptr`, `constexpr`, `enum class`, range-for, move 문법 및 C++11 이후 문법을 사용하지 않는다.
- namespace를 사용하지 않는다. 전역 심볼은 `DF_Main_`, `DF_Rod_`, `DF_Protocol_` 또는 기능이 드러나는 고유 접두어로 충돌을 방지한다.
- 제품 Variant용 `#if/#ifdef/#else/#endif`를 새로 만들지 않는다. 헤더는 `#pragma once`, 상수는 C++03 호환 `enum`, `const`, `extern` 선언/정의를 사용한다.
- compile/link 빌드는 사용자 사전 승인 후에만 Codex가 실행하고 결과를 기록한다. 플래시, 장비 시험 및 최종 장비 검증은 사용자가 수동 수행한다.
- 검증은 변경 위험에 비례해 준비하되 실제 수행 여부와 결과를 사실대로 기록한다.
- 비밀정보, 자격 증명, 토큰, 개인 장비 주소를 코드·문서·로그에 기록하지 않는다.
- 명시적 요청 없이 commit, push, flash, 배포 또는 외부 시스템 변경을 수행하지 않는다.
