# DF AP 연동 프로토콜

## 목적

이 문서는 AP 애플리케이션과 DF MAIN 펌웨어 사이의 시리얼 연동 규약을 정의한다. AP는 MAIN에만 연결하며, MAIN은 ROD 관련 상태와 명령을 내부 MAIN–ROD 통신으로 중계한다.

> 상태: 통합 기준 사양. 현재 배포된 TestModule과 펌웨어 동작을 기준으로 정리했다. 호환성 검토 없이 기존 PID, payload 형식 또는 타이밍을 바꾸지 않는다.

## 기준 펌웨어 버전

| 구성 | 기준 버전 | 펌웨어 응답 표기 |
| --- | --- | --- |
| MAIN | v1.0.10.0 | `Vm1.0.10.0` |
| ROD | v1.0.2.0 | `Vr1.0.2.0` |

이 문서의 AP 연동 사양은 위 버전을 기준으로 한다. 새 버전에서 PID, payload 형식, 초기화 순서 또는 OTA 동작이 변경되면 이 표와 관련 사양을 함께 갱신한다.

## 전송 계층

| 항목 | 값 |
| --- | --- |
| 물리 연결 | MAIN USB CDC 시리얼 |
| 통신 속도 | 115200 bps |
| 문자 인코딩 | ASCII 호환 출력 가능 문자 |
| AP 요청 형식 | `$` + 명령 + `%` |
| MAIN 응답 형식 | `$` + 응답 + `%` |
| 프레임 종료 문자 | `%` 한 개가 정확히 한 프레임을 끝냄 |
| 수신 복구 | 새로운 `$` 수신 시 이전 미완성 프레임을 폐기하고 다시 시작 |

시리얼 드라이버는 하나의 프레임을 나누거나 여러 프레임을 합쳐 전달할 수 있다. AP는 `%`까지 수신 데이터를 버퍼링하고, 완성된 모든 프레임을 순서대로 처리해야 한다. 형식이 맞지 않거나 지나치게 긴 미완성 프레임은 폐기한다.

## 연결 및 초기화

초기 연결 중 MAIN은 명령을 한 번에 하나씩 처리한다. 초기화 명령을 하나의 burst로 전송하지 않는다.

1. 시리얼 포트를 열고 AP 수신 버퍼와 프레임 decoder 상태를 초기화한다.
2. 500 ms 대기한다.
3. 각 명령 사이를 최소 60 ms 띄우며 `$00%`, `$290101%`, `$1101%`을 순서대로 전송한다.
4. 500 ms 대기한 뒤 `$00%`, `$080%`을 전송한다.
5. 다시 500 ms 대기한 뒤 `$00%`, `$0112%`, `$0110%`, `$0115%`, `$0117%`, `$1501%`을 순서대로 전송한다.
6. 위 초기화가 끝난 뒤에만 일반 polling을 시작한다. 표준 polling 주기는 2초다.
7. `$00%`으로 polling한다. ROD와 IMU 연결 상태를 받은 뒤 `$10%`으로 버전을 한 번 조회한다.

AP는 포트를 열었다는 사실만으로 MAIN, ROD 또는 IMU가 준비되었다고 판단하면 안 된다.

## 공통 AP 요청

| 프레임 | 방향 | 의미 | 비고 |
| --- | --- | --- | --- |
| `$00%` | AP → MAIN | 현재 상태 요청 / 일반 polling | 초기화 뒤 사용하며 표준 주기는 2초다. |
| `$10%` | AP → MAIN | 버전 정보 요청 | 연결 상태 확인 뒤 조회한다. |
| `$290101%` | AP → MAIN | AP/TestModule 운용 context 설정 | 기존 초기화 순서에서 사용한다. |
| `$1101%` | AP → MAIN | 프로그램/제어 상태 시작 | 기존 초기화에서 status polling 전에 필요하다. |
| `$080%` | AP → MAIN | 초기화 제어 요청 | 호환성을 위해 형식을 유지한다. |
| `$0112%`, `$0110%`, `$0115%`, `$0117%`, `$1501%` | AP → MAIN | 기존 초기 상태·설정 요청 | 펌웨어 동작을 명시적으로 변경하지 않는 한 정해진 초기화 순서에서만 전송한다. |
| `$1800%` | MAIN → AP | AP 종료 요청 | 로그와 경고를 남긴다. `$1800%`을 자동 회신하거나 Windows를 자동 종료하지 않는다. |

## MAIN 상태 및 이벤트 메시지

| 접두어 | 방향 | 의미 | AP 처리 |
| --- | --- | --- | --- |
| `$10` | MAIN → AP | 펌웨어 버전 정보 | 값이 쉼표로 구분되어 있으면 파싱하여 MAIN/ROD/IMU 버전을 표시한다. |
| `$09` | MAIN → AP | 장비/상태 정보 | 쉼표로 구분된 상태 payload를 파싱한다. |
| `$20xx%` | MAIN → AP | ROD 연결 상태 | `xx = 01`은 연결됨, `00`은 미연결이다. |
| `$21xx%` | MAIN → AP | IMU 연결 상태 | `xx = 01`은 연결됨, `00`은 미연결이다. |
| `$12...%` | MAIN → AP | 배터리 상태 | 상태 값으로 표시한다. |
| `$14...%` | MAIN → AP | 엔코더 상태 | 상태 값으로 표시한다. |
| `$13xx...%` | MAIN → AP | 장비/오류 상태 | `xx`를 두 자리 상태 코드로 처리한다. |
| `$27...%` | MAIN → AP | 사용자 입력 이벤트 | 활성 제품 입력 mapping에 맞춰 해석한다. |
| `$30xx...%` | MAIN → AP | 추가 장비 상태 | `xx`를 두 자리 상태 코드로 처리한다. |

알 수 없는 프레임은 조용히 버리지 말고 AP 로그에 남긴다. 이후 펌웨어에서 추가된 기능일 수 있다.

## LM JIG 제어

LM 명령은 MAIN의 런타임 구성이 `DF_CONFIG_LMJIG`로 판별된 경우에만 유효하다. 일반 MAIN 구성에서는 `$07`이 예약 명령이므로 성공한 모터 동작으로 처리하면 안 된다.

| 프레임 | 방향 | 의미 |
| --- | --- | --- |
| `$070%` | AP → MAIN | LM 모터 정지 |
| `$071dddtttt%` | AP → MAIN | LM 모터 CW 구동. `ddd`: duty 000–255, `tttt`: 동작 시간(ms), 0000은 시간 자동 정지 없음 |
| `$072dddtttt%` | AP → MAIN | LM 모터 CCW 구동. 필드 형식은 `$071`과 같다. |
| `$0750%` | AP → MAIN | LM 위치 제어 preset 0 |
| `$0751%` … `$0754ddd%` | AP → MAIN | LM 위치 제어 및 파라미터가 있는 복귀/home 명령 |

LM 위치 제어에서 펌웨어는 목표 센서 감지 또는 3초 안전 timeout 시 모터를 정지한다. AP는 요청 전송 성공만으로 실제 이동 성공을 판단하지 말고, 센서/상태 응답으로 결과를 확인해야 한다.

## ROD 무선 OTA 중계

ROD 무선 OTA는 시리얼 프로토콜 안에 16진수 바이너리 프레임을 넣어 MAIN을 경유한다.

| 항목 | 값 |
| --- | --- |
| AP 시리얼 wrapper | `$OR` + 대문자 16진수 OTA 프레임 + `%` |
| OTA 바이너리 marker | `DFRO` |
| 프로토콜 버전 | 1 |
| OTA data payload 최대 | 프레임당 96 bytes |
| 무결성 | OTA 프레임별 CRC-32, 전체 이미지 SHA-256 |
| 전송 순서 | Start → 순차 Data → Finish, 각 프레임별 ACK 대기 |
| 재시도 | timeout이면 같은 프레임을 재전송하며, ACK 검증 전 sequence를 증가시키지 않음 |
| 취소 | 취소 또는 AP 오류 시 활성 세션 Abort 프레임 전송 |

MAIN은 잘못된 OTA 형식에 `$OE1%`, OTA 사용 불가·busy·ROD 미연결 상태에 `$OE3%`, MAIN이 ROD로 중계하지 못한 경우에 `$OE5%`를 응답할 수 있다.

OTA ACK는 `$OR` + 16진수 ACK 프레임 + `%` 형식이다. AP는 다음 항목을 모두 검증한 뒤에만 다음 프레임으로 진행한다.

- marker와 프로토콜 버전
- CRC
- session ID와 sequence
- ACK 상태
- next sequence와 누적 기록 byte 수

Finish ACK 성공 뒤에는 MAIN polling을 즉시 재개한다. 최대 12초 동안 `$2001%` ROD 재연결을 기다린 뒤 `$10%`을 한 번 전송해 재부팅 뒤 ROD 버전을 조회한다. 완료 UI에는 전송 완료와 ROD 재연결 확인 여부를 구분해 표시한다.

## AP 구현 요구사항

- 연결 초기화와 OTA 중에는 명령 전송을 직렬화한다.
- 모터·업데이트 명령을 전송하기 전에 정확한 길이와 숫자 범위를 검증한다.
- `$00%` polling은 초기화 완료 뒤에 시작하고, OTA 전송 완료 또는 실패 처리가 끝나면 재개한다.
- 송신·수신 프레임을 timestamp와 함께 기록한다. `$1800%`과 프로토콜 오류를 숨기지 않는다.
- 연결 상태, 버전 응답, 물리 동작 결과는 서로 독립된 사실로 관리한다.
- 명시적인 작업자 조작 없이 자동 flash, PC 재부팅·종료 또는 MAIN 종료 요청 ACK를 수행하지 않는다.

## 호환성 규칙

- 기존 PID와 payload 위치는 배포된 MAIN/ROD 펌웨어와의 호환성 계약이다.
- 새 기능은 새 PID로 추가하며 기존 PID의 의미를 바꾸지 않는다.
- 새 선택 응답 필드는 기존 수신기가 해석할 수 있는 호환 형식으로 뒤에 추가한다.
- 시리얼 framing, OTA 프레임 형식, 타이밍 또는 모터 의미를 바꾸려면 AP와 펌웨어를 짝으로 릴리스하고 통합 검증해야 한다.
